# ADR 0003: IPC Envelope Contract

- **Status:** Accepted
- **Date:** 2026-07-02
- **Deciders:** Vinz
- **Supersedes:** —

## Context

ADR 0001 fixed the transport: `window.chrome.webview.postMessage` (frontend → host)
and `CoreWebView2.PostWebMessageAsJson` (host → frontend). This ADR fixes the
message contract on top of that transport. The contract must stay
transport-agnostic so a later Kestrel variant (ADR 0001, deferred alternative)
only replaces the outermost layer.

## Decision

### Envelopes

```jsonc
// Frontend → Host: request
{ "id": "<uuid>", "module": "inventory", "action": "getHardwareInfo", "payload": { } }

// Host → Frontend: response, correlated by id — exactly one per request
{ "id": "<uuid>", "success": true,  "data": { } }
{ "id": "<uuid>", "success": false, "error": { "code": "ACCESS_DENIED", "message": "…", "details": null, "requiredPrivilege": "ADMINISTRATOR" } }

// Host → Frontend: unsolicited event
{ "type": "event", "module": "inventory", "event": "scanProgress", "payload": { "percent": 40 } }
```

### Wire conventions

| Rule | Value |
|---|---|
| Property names | camelCase (`JsonSerializerDefaults.Web`) |
| Enum values | SCREAMING_SNAKE strings (`ACCESS_DENIED`, `REQUIRES_ELEVATION`, `ADMINISTRATOR`) |
| Correlation | `id` is generated by the caller (`crypto.randomUUID()`), echoed verbatim in the response |
| Missing/`null` payload | treated as `{}` by the host |
| Timeouts | client-side only (default 10 s in `bridgeClient.ts`); the host always answers |

The original sketch mixed enum casings (`ACCESS_DENIED` vs `Administrator`);
this ADR normalizes to one rule — every enum is SCREAMING_SNAKE on the wire.

### Error codes

`INTERNAL_ERROR`, `ACCESS_DENIED`, `NOT_FOUND`, `WMI_UNAVAILABLE`,
`INVALID_REQUEST`, `UNKNOWN_ACTION`, `NETWORK_PROBE_FAILED`,
`EVENT_LOG_UNAVAILABLE`, `FILE_WRITE_FAILED`, `DIRECTORY_UNAVAILABLE`
(C# source of truth: `Wec.Core.Results.ErrorCode`).
`ACCESS_DENIED` errors carry `requiredPrivilege` (ADR 0002).

### Dispatch rules (host)

1. Message is parsed as a request envelope. Unparseable messages or messages
   without an `id` are logged and dropped (no correlation possible).
2. Missing `module`/`action` → `INVALID_REQUEST` response.
3. Routing key is `(module, action)` → registered `IActionHandler`; no match →
   `UNKNOWN_ACTION`. Duplicate registrations fail at startup, not at dispatch.
4. The dispatcher deserializes `payload` into the handler's `TPayload`,
   invokes `HandleAsync`, and maps `Result<T>` onto the response envelope.
   Payload shape mismatch → `INVALID_REQUEST`.
5. Handler exceptions are bugs (ADR 0002): logged with full detail, answered
   with a generic `INTERNAL_ERROR` that leaks no internals.
6. Every dispatch runs in a logging scope with `CorrelationId` (= `id`),
   `Module`, `Action`.

### Handler model

Handlers implement `IActionHandler<TPayload, TResult>` (Wec.Core), receive a
typed payload, and return `Result<TResult>`. They never see JSON, envelopes,
or WebView2 types — that is the bridge layer's job (`Wec.Host/Bridge`).

Handlers are resolved from a DI scope per request so they can depend on
scoped services (DbContext etc.). Uniqueness of `(module, action)` across all
registrations is validated once at startup.

### Events

Events are fire-and-forget host → frontend notifications; no acknowledgement,
no correlation. `bridgeClient.ts` exposes `subscribe(module, event, callback)`.
The host-side publisher abstraction is deliberately **not** built yet — no M1
feature emits events; it will be added with the first feature that needs it.

## Consequences

- One dispatcher, one JSON configuration (`BridgeJson`), uniform error mapping.
- Handlers are unit-testable without any transport or JSON concerns.
- The dropped-message case (no `id`) is invisible to the frontend by design;
  client-side timeouts surface it as `BridgeTimeoutError`.
- Manual TS/C# DTO sync (`shared/api-types.ts`) remains a known risk until the
  DTO count justifies a generator (architecture plan §5).
